# Walk — Designer composes an H4-filtered, ATR-stopped long (`d18`)

**Spine `r2.s2`, RELEASE.md ledger `d18`.**

> This walk proves the spine's end state on a MacBook: the operator describes
> in the Designer "a long that enters on M15 RSI oversold only while the H4
> EMA(200) is rising and stops at 2×ATR(14)"; the composed DSL carries the
> `htf`-series filter and the `AtrStop` **with no substitution**; the Library
> node's summary line renders `h4:ema(200)` and `atr(14)×2`; and Backtest
> Lab's trade log reads each trade's stop at the ATR-derived distance. It is
> dispatched as an **Orca session in the `macbook` environment** (ruling a14).
> The stopwatch runs from the Designer prompt's submission to the run's trade
> log visible in Backtest Lab; the budget is **10 minutes**.

## Setup (preconditions — done before the timer starts)

1. **Seeded fixture.** The Release 1 fixture is in place: BTCUSDT **M15 and
   H4** CandleSeries snapshots at a pinned `data_version`, and a migrated
   `pulse.db` at `~/Library/Application Support/PulseTrader/pulse.db`. Record
   the pinned `data_version` — the run below must carry it. **Both** series
   must be present: the H4 snapshot is what the `htf` operand reads, and a
   fixture seeded M15-only makes Step 3 fail with `HtfRequired`, not a bug.
2. **Bundle built.** `just bundle` has produced
   `/Applications/PulseTrader.app` (or the walker's local equivalent) at the
   current head — the build must include this item's formatter and w3's
   composer tokens.
3. **App running.** `PulseTrader.app` was launched from Finder and is sitting
   on the Strategy Library.
4. **Composer vocabulary present.** This walk assumes w3's composer tokens —
   the `htf` operand and the `AtrStop` rule — are available to the composer,
   either in the shipped `composer.md` inside the bundle or in the operator's
   `$PULSE_PROMPT_DIR` overlay. If the bundle predates w3's merge, point
   `$PULSE_PROMPT_DIR` at an overlay carrying them and relaunch the app before
   the timer starts. **Composer vocabulary is the one thing this walk cannot
   prove** — it is w3's deliverable; this runbook only reads its effect.

## The walk (stopwatch starts at the prompt's submission)

**Step 1 — Compose the strategy in the Designer (budget: ~4:30)**
- Open the Designer and submit: *"a long that enters on M15 RSI oversold only
  while the H4 EMA(200) is rising and stops at 2×ATR(14)"*. Watch the streamed
  build steps, then review the accepted card before accepting.
- *Expected output:* the accepted card's summary shows a filter line carrying
  an `h4:` operand (e.g. `h4:close > h4:ema(200)` or the rising-slope
  equivalent the composer built) and an exit line `atr(14)×2` — U+00D7, not
  `x`, and never `atr_stop …` / `atr stop …`. **No substitution**: if the
  card shows a same-timeframe filter or a percent stop instead, the composer
  silently dropped the construct — that is a failure to report, not a shape
  to accept.

**Step 2 — Read the Library node's summary line (budget: ~1:00)**
- Accept the card so the version persists, then open the Strategy Library and
  select the new version's node.
- *Expected output:* the node's summary line and the details pane's "DSL
  summary" read the same words the card showed — a filter line containing
  `h4:ema(200)` and an exit line `atr(14)×2`. Identical strings on both
  surfaces is the consolidation claim itself: the card and the Library are
  two DTO adapters over one domain formatter.

**Step 3 — Run it in Backtest Lab (budget: ~4:00)**
- Open Backtest Lab, select the version, and run it on the default window.
- *Expected output:* the run completes against the pinned `data_version` and
  the trade log renders a `stopPrice` column (w2's surface) whose value
  **differs per trade** — each row's stop sits at that trade's ATR-derived
  distance, not one fixed percent. Pick any two rows and check R-consistency:
  the recorded R equals `|entry − stop|` scaled by the position, i.e. the
  stop distance the ATR computed is the one the risk math used.

**Stopwatch stops** when the run's trade log is visible in Backtest Lab (end
of Step 3). Target: **≤ 10:00** from the Step 1 submission.

## Report back

The walk report records:

- elapsed wall-clock (prompt submitted → trade log visible in Backtest Lab);
- the accepted `version_id` and the run's `run_id`;
- the pinned `data_version` the run carried;
- a screenshot of the accepted card (or the Library node's summary line)
  showing `h4:ema(200)` and `atr(14)×2`;
- a screenshot of the Backtest Lab trade log with the per-trade `stopPrice`
  column;
- any step whose actual output diverged from *Expected output*.

## Recovery (if something breaks mid-walk)

- **The composer substitutes** (a same-timeframe `ema(200)` filter, or a
  `stop 5%` in place of the ATR stop): the prompt vocabulary is stale —
  precondition 4. Point `$PULSE_PROMPT_DIR` at the overlay carrying w3's
  tokens (or rebuild the bundle past w3's merge), relaunch, and re-run Step 1.
  Record the substitution verbatim in the report — a substituted card is
  *not* a pass with a note.
- **Step 3 fails `HtfRequired` / "no H4 snapshot":** the fixture carries M15
  only, or the run's `data_version` does not name the pinned snapshot.
  Re-check precondition 1 — the H4 CandleSeries must exist at the same
  `data_version` the run reads.
- **The card and the Library line disagree** (Step 2): that is exactly the
  drift this item deletes — it means the binary predates the formatter or a
  renderer survived. Re-check precondition 2's build head; if the head is
  right, the failure is real — capture both strings and report.
- **The exit reads `atr stop 14 x2` or `atr_stop 14 x2`:** the pre-item
  vocabulary — same cause and remedy as the previous entry.
- **`stopPrice` is absent or constant (Step 3):** the trade-log column is
  w2's engine work — if the bundled binary predates w2's merge the column
  cannot exist; rebuild or record the absence as a fixture gap, not a w4
  failure. A constant column under an `atr(14)×2` exit is a real finding.
- **Over budget at Step 1:** the compose round-trip is the slow step. Keep
  the stopwatch running and record the real elapsed — the report takes the
  true number, not a trimmed one.
